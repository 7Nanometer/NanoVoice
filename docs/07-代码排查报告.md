## 第一段：配音质量问题（最重要）

### 1. 参考音频指向 6 月未降噪的旧素材 ⭐ 最大单点收益

- **位置**：`config.py` 第 138-142 行 `REF_AUDIO`
- **现状**：指向 `GPT-SoVITS/logs/7Nanometer/5-wav32k/阿基拉.mp3_...wav`
  （6 月原始素材，**未降噪**）。而模型是在 `7Nanometer_v2/`（降噪后的 165 条）上训练的。
- **影响**：相当于"在干净数据上训练、却拿带杂音的样板去生成"——10-08 已实测：
  底噪 −43.4 → −54.4 dB、高频噪声降 4 倍（"沙哑"的来源）、
  "渡边信一郎"这个词只有换成新样板后才念对。
- **建议改法**（已实测新样板，6.4 秒、无削顶、底噪干净）：
  ```python
  # config.py 第 138-142 行，REF_AUDIO 的默认值改为：
  GPT_SOVITS_DIR / "logs" / "7Nanometer_v2" / "5-wav32k"
  / "clean_32k.wav_0000104320_0000310080.wav"
  ```
- **必须同步改 `REF_TEXT`**（第 147-151 行）——文本必须与该音频一字不差，
  新音频对应的文本（从训练标注 `2-name2text.txt` 第 2 条抄来）：
  ```python
  REF_TEXT = os.getenv(
      "REF_TEXT",
      "一九八零年,二十六岁的大游克阳凭借着童梦这部作品获得了第四届日本大赏.",
  )
  ```
- **影响面**：只改推理时的"音色样板"，改完立即生效，**不需要重新训练**。

### 2. 响度拉平的两个副作用：削顶 + 情感被抹平

- **位置**：`speech_synthesizer.py` 第 396-397 行（逐句拉音量）+ 第 412-420 行（拼接导出）
- **现状**：每句都被拉到统一的 −20 dBFS，然后直接相加导出，没有峰值保护。
- **影响**：10-08 实测——①成品峰值顶到 **0.00 dBFS 削顶**（爆音）；
  ②句子间自然的强弱起伏被拉平（听感"没有情感波动"）。
- **建议改法**（两处，合计不到 10 行，建议一起做）：
  ```python
  # ① 【治削顶·必做】speech_synthesizer.py 第 412-420 行，
  #    拼接完成、导出之前，加一道"峰值保护"——峰值超过 -1 dBFS 就整体等量降下来：
  peak = combined.max_dBFS
  if peak > -1.0:
      combined = combined.apply_gain(-1.0 - peak)
  #    （整体等量降低不破坏句间比例，只防爆音）

  # ② 【保情感·建议】从"强行拉平"改成"轻微矫正"：
  #    config.py 第 174 行：
  TARGET_DBFS = float(os.getenv("TARGET_DBFS", "-18.0"))
  #    speech_synthesizer.py 第 305 行：
  def _match_loudness(segment, target_dbfs, max_adjust_db=6.0):   # 原 12.0
  ```
  ① 解决"峰值顶到 0 dBFS"的爆音；② 让句子间自然的强弱起伏保留下来
  （单句最多只调 6 分贝，不再"强行全拉平"）。

### 3. 切块 100 字太长 + 硬切会切断词

- **影响**：10-08 实测——同样一句话 4 遍里 2 遍把"就那种"念成"卷骂种"；


## 第二段：程序行为问题

### 5. 语速/音量滑块在"语音克隆"模式下无效（静默失效）

- **位置**：`speech_synthesizer.py` 第 168 行（`"speed": 1.0` 写死）；
  `generate_audio_from_script` 的 rate/volume 只在微软语音分支使用
- **现状**：勾选"使用克隆声音"后，拖动语速/音量**没有任何效果**——界面上没有任何提示。
- **建议改法**（推荐 a）：
  - a. 把语速换算后传给克隆引擎：`payload["speed"] = 1.0 + rate/100`
    （注意只在 ±20% 内可靠，超出会变调）；音量可用导出后增益处理。
  - b. 简单法：克隆模式下把这两个滑块置灰，并注明"本地克隆暂不支持"。

### 6. Ctrl+C / 关闭窗口时，语音引擎进程不会被清理

- **位置**：`webui/server.py` 第 466 行 `uvicorn.run(...)`（无退出清理逻辑）
- **现状**：旧版 `main.py` 退出时会把 GPT-SoVITS 子进程一起关掉；新版没有这段 ——
  异常退出后可能留下"孤儿进程"持续占着显存（8GB 显卡上是实打实的资源）。
- **建议改法**：在 `main_entry` 里包一层 try/finally（仿照 main.py 末尾的写法）：
  ```python
  try:
      uvicorn.run(app, ...)
  finally:
      if gpt_sovits_process is not None and gpt_sovits_process.poll() is None:
          gpt_sovits_process.terminate()
  ```
  （需要把 main.py 里的全局 `gpt_sovits_process` 引入或改由 server.py 自行记录）

### 7. 配音任务异常卡死后，会永久锁死后续合成

- **位置**：`webui/server.py` 第 346-349 行（"已有一个配音任务正在进行"）
- **现状**：判断"是否有任务在跑"只认 `status == "running"`。
  万一某次合成线程卡死（显卡驱动异常等），这条任务永远 running，
  后续合成全部被拦——**只能重启整个程序才能恢复**。
- **建议改法**：加"僵尸任务"判定：
  ```python
  ZOMBIE_AFTER = 30 * 60   # 30 分钟还没结束视为卡死
  for tid, t in SYNTH_TASKS.items():
      if t.get("status") == "running" and time.time() - t.get("started_at", 0) > ZOMBIE_AFTER:
          t.update(status="error", message="任务超时（视为卡死）")
  ```

### 8. 上传文件没有大小限制（读文件全进内存）

- **位置**：`webui/server.py` 第 236 行 `data = await f.read()`
- **现状**：上传多大的文件就一次性读进内存。正常文章/录音远小于此，
  但误拖一个大视频（几 GB）会让内存瞬间吃满、程序崩溃。
- **建议改法**：分块读+写盘，并加 50MB 上限：
  ```python
  MAX_UPLOAD = 50 * 1024 * 1024
  size = 0
  with open(target, "wb") as out:
      while chunk := await f.read(1024 * 1024):
          size += len(chunk)
          if size > MAX_UPLOAD:
              out.close(); target.unlink(missing_ok=True)
              return {"ok": False, "error": "文件超过 50MB 上限"}
          out.write(chunk)
  ```

### 9. 前端合成轮询在网络持续失败时会无限继续

- **位置**：`webui/static/js/app.js` 的 `pollSynth()`（catch 后 continue）
- **建议改法**：连续失败计数，超过 10 次停止轮询并提示"连接中断，请刷新页面查看结果"。

### 10. 行内 Markdown 符号可能被念出来

- **位置**：`speech_synthesizer.py` 第 71-75 行 `sanitize_for_tts`
- **现状**：已清理【】和行首符号，但**行内**的 `**加粗**`、`` `代码` ``、
  `[文字](链接)` 还没清——可能被念成"星号星号"。
- **建议改法**：追加两行清理：
  ```python
  text = re.sub(r"\*\*|__|`+", "", text)                        # 去加粗/代码符号
  text = re.sub(r"\[([^\]]*)\]\([^)]*\)", r"\1", text)          # 链接保留文字
  ```

### 11. 断句标点不全（省略号、英文标点不打断）

- **位置**：`speech_synthesizer.py` 第 100 行（`if char in "。！？；\n"`）
- **建议改法**：改为 `"。！？；…\n"`；如常处理英文文案，另加 `".!?"` 的处理
  （注意规避小数点和网址：简单做法是要求后面跟空格或行尾）。
