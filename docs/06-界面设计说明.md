# 界面设计说明（新版"暗色录音棚"）

> 这篇文档记录新版界面的设计思路和具体做法，
> 写论文的"界面设计"章节、或答辩讲"视觉实现"时可以直接参考。

---

## 一、为什么重做界面

改造前的界面是用 Gradio（一个 Python 界面库）自动生成的，功能齐全，
但外观完全由框架决定：白底、灰边框、橙色方块，和"语音"这个主题毫无关联，
所有区块视觉重量一样，看不出重点。

重做遵循一条原则：**功能代码一行不动，只换"外壳"。**
所有干活的函数（抓文章、生成文案、配音）还是原来那些，
新界面只是换了一种方式把它们展示出来、连起来。

## 二、设计概念：「暗色录音棚」

整个界面的视觉母题只有一个：**声波**。

这个系统的本质是"把文字变成声音"，所以选择"声音"最直观的图形符号
（声波）作为贯穿全站的设计元素，让它反复出现、处处呼应：

| 出现的地方 | 形态 |
|---|---|
| 左上角标志 | 五根高低错落的声波竖条 |
| 首屏背景 | 五条缓缓流动的正弦波（程序实时绘制） |
| 每个卡片标题旁 | 迷你声波小标记 |
| 导航标签的序号 | 机械面板式的 01 / 02 |
| 等待合成时 | 跳动的声波柱动画 |
| 小图标 / 网站图标 | 同款声波 |

一个元素反复出现就是"设计语言"——这是获奖级网站的共同特征：
让人看完记得住"那个波浪"。

**为什么是暗色**：声音主题天生适合暗色——光在暗处才亮得出来。
底色用接近纯黑的深夜黑（#0A0A0C），
主色"声波青绿"（#34D399）只用在"要你动手的地方"（按钮、焦点、进行中），
琥珀色只做极小面积的点缀（提醒）。
规矩：整页 90% 是黑与灰的层次，彩色只给"行动"。

## 三、八个方面的具体做法

### 1. 排版
- 中文字体用**思源黑体**（免费可商用），英文数字用 **Inter**
  （浏览器自动分工：英文用 Inter、遇到汉字自动落到思源黑体，中英混排最佳效果）；
- 正文字距、行高按中文阅读习惯调宽（行高 1.7~2.0）；
- 大标题开启 `palt`（比例标点）——中文排版的专业开关，
  让逗号句号只占半个字宽，大字标题不被标点撑出空档。

### 2. 留白
- 首屏上留白随屏幕高度自动伸缩（矮屏收紧，保证工作区露头）；
- 卡片内边距 26px，卡片间距 24px，统一节奏；
- 空状态盒在卡片里撑满剩余高度，不留尴尬的空档。

### 3. 视觉层级
- 一屏之内只有一个"最大"的元素（首屏大标题）；
- 每张卡片一个标题 + 一段说明 + 一组控件，层级固定不抢戏；
- 主按钮（青绿实心）全站只出现在"主行动"上（生成 / 合成），
  其余按钮一律幽灵样式（透明底描边）。

### 4. 色彩
- 单一主色（青绿）+ 中性灰阶 + 稀有琥珀，见上文；
- 暗色下不用"阴影"表达层次（看不见），改用**发光**（glow）；
- 背景铺了两层极淡的彩色光晕 + 一层噪点颗粒——
  噪点是质感的关键：纯色背景怎么看都像塑料，撒上肉眼几乎不可见的
  颗粒立刻变成"有质感的暗"。

### 5. 动效
全部动效遵循一条纪律：**有意义才动**。
- 首屏声波：缓慢流动，是"声音"的具象化；
- 标题里「开口说话」四个字**逐个从模糊中显现**——像被一个字一个字
  念出来，是这个系统主题的视觉版；
- 界面在干活时（生成 / 合成中），首屏声波**加速流动**——
  "系统正在思考"这件事变得看得见；
- 入场动画等待字体加载完成后才播放，标题第一次露面就是最终字体，
  不会先闪一下系统默认字再跳变。

### 6. 微交互
- 按钮：悬停微微上浮 + 一道柔光扫过（仅主按钮）+ 按下微缩；
- 拖拽区：文件拖到上方时虚线变实线、整块泛青光，"松手就行"不言自明；
- 输入框：聚焦时边框亮起青绿 + 外发光；
- 滑块：悬停圆点放大，已滑过的部分染成主色；
- 顶栏：页面滚动后底色变实并落下淡影，提醒"这层浮在内容上面"；
- 进度条：悬停变粗并冒出圆点，好点也好看；
- 通知气泡：右下角滑入，左侧一条状态色竖线（绿=成功/红=失败/琥珀=提醒）。

### 7. 响应式
- 宽屏（>1080px）：双列布局，右列"跟着视线走"（滚动时钉住），
  左列再长右边的结果和按钮也一直看得见；
- 窄屏：自动变单列，一切全宽，手机上也能完整操作；
- 配合屏幕高度：卡片比屏幕高的设备上自动取消"钉住"，
  避免按钮够不到；
- 系统开启"减少动画"时，所有动效自动关闭（尊重用户设置）。

### 8. 原创性
- 不从任何现成 UI 框架/模板拼装：所有控件（滑块、开关、下拉、
  播放器、拖拽区）都是手写样式；
- 所有图标是手绘的 SVG 线稿，风格统一（统一线宽、圆头）；
- 视觉母题（声波）是为这个系统**原创**的设计语言，
  不是套用任何网站的样式。

## 四、技术架构（为什么这么做）

```
浏览器里的网页（webui/static/）
   HTML + CSS + 原生 JS，无任何框架、无构建步骤
        ↓ 通过 /api/xxx 接口呼叫
Python 后端服务（webui/server.py，基于 FastAPI）
        ↓ 直接调用
原有业务函数（main.py 等，一行没改）
```

几个关键决策：

- **不用前端框架**：界面不复杂，原生三件套足够，
  而且没有"打包构建"环节——改一行样式刷新页面就见效，最不容易坏；
- **接口与原功能一一对应**：网页上每个按钮背后就是一个接口，
  后端只是"转接"，不新增业务逻辑；
- **配音任务做成"下单-取号"**：配音要跑几分钟，网页立刻拿到任务号，
  每秒问一次"好了吗"，期间界面完全不卡（旧界面转圈期间整个页面是卡死的）；
- **字体本地自带**：思源黑体压缩成 woff2（17MB→7.4MB）放在项目里，
  断网也不会掉字体——答辩现场网络不可控，这条是保险。

## 五、以后想改样式，改哪里

所有视觉参数集中在 `webui/static/css/style.css` 顶部的 `:root{}` 变量区：

| 想改什么 | 改哪个变量 |
|---|---|
| 主色（青绿） | `--mint` 及同组三个 |
| 背景色 | `--bg` |
| 圆角 | `--r-lg` / `--r-md` / `--r-sm` |
| 动效节奏 | `--ease` |
| 字体 | `@font-face` 段 + `--font-sans` |

改完全局生效。页面文字（标题、按钮文案）在 `webui/static/index.html` 里。
